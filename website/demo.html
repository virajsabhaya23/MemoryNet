A three-minute walkthrough, read-only replay.

MemoryNet flags the pinned task, blocks its stale context export, and gives the next agent the replacement with citations.

This replay comes from an executed, isolated integration run. Evidence, extraction responses and approvals are synthetic fixtures. The database, quote validation, review rules, MCP clients and export checks are real. No live model call or coding-agent implementation is represented.

  1. Extract a decision with an exact quote

    AI Decision Extraction (Decision Guard) checks each quotation against the selected source. This offline run supplies a scripted response through the same validation path used by Meta.

  2. Keep suggestions out of authoritative context

    The candidate enters review as a pending proposal. An MCP query returns no_results before approval. The agent’s attempt to approve is refused.

    A distinct fixture reviewer approves the exact proposal revision. In a real workflow, this is an authorized person reviewing the evidence.

  3. Deliver approved context and pin the task

    A real MCP SDK client retrieves guidance for repository 1001, branch main. The task “Update transport retries” pins that exact decision.

    Initial work baseline: current. Context export succeeds.

  4. Reverse the decision. See the affected work.

    A replacement proposal removes HTTP 429 retries. Its scripted conflict hint names decision 33b44c5a-fd89-4bf2-b6be-901e4aeb67ae, revision 1. The original remains authoritative while the replacement is pending.

    After the fixture reviewer approves the replacement, Stale-Work Radar (Affected work) finds the task pinned to superseded guidance.

    Refreshing an agent query does not silently update the task’s baseline. A person must review the affected work and record a new baseline.

    review_neededstale context export blocked

    A second MCP SDK client receives only the replacement decision and its source citations.

    Replacement creates a new decision ID at revision 1. These are successive policies, not revision 1 and revision 2 of one record.
